# Lab 7B: สกัดแผนการศึกษาจากเล่มหลักสูตรด้วย Local LLM

โปรเจกต์นี้เป็นส่วนหนึ่งของแล็บ **Lab 7B** ซึ่งมุ่งเน้นการพัฒนาระบบสกัดข้อมูลแผนการศึกษา (รายวิชา, หน่วยกิต, หมวดวิชา, ปี/ภาคเรียน ฯลฯ) จากเล่มหลักสูตรที่เป็นไฟล์ PDF โดยมีข้อกำหนดสำคัญคือ **ต้องใช้โมเดล LLM ที่รันบนเครื่องตัวเอง (Offline 100%)** ผ่านทาง Ollama เพื่อความประหยัด ความเป็นส่วนตัวของข้อมูล และความสามารถในการทำซ้ำ (Reproducibility)

---

## 📂 โครงสร้างโฟลเดอร์และไฟล์ (Project Structure)

- **`lab7b_curriculum.py`**: โค้ดหลัก (Main Script) สำหรับรัน Pipeline สกัดข้อมูล ประกอบด้วยฟังก์ชันการทำ OCR, การเชื่อมต่อกับ Ollama, การรวมผลลัพธ์แบบ Chunk, และฟังก์ชันสำหรับตรวจสอบความถูกต้องแบบ Rule-based
- **`Lab7B_Curriculum_LocalLLM1.pdf`**: เอกสารคำอธิบายโจทย์ ข้อกำหนด และวิธีการทำแล็บ 7B
- **`data/`**: โฟลเดอร์เก็บไฟล์ข้อมูลดิบ (Input) เช่น ไฟล์ `DSBA_curriculum.pdf` (เอกสารหลักสูตรที่ต้องการสกัดข้อมูล)
- **`gt/`**: โฟลเดอร์เก็บข้อมูลเฉลย (Ground Truth) เช่น `DSBA_academic_plan_coop.json` เพื่อใช้สำหรับประเมินผลความแม่นยำ
- **`output/`**: โฟลเดอร์สำหรับบันทึกผลลัพธ์จากการรันโปรแกรม รวมถึงผลการประเมิน
  - `pred_text.json`: ผลลัพธ์ข้อมูลรายวิชาที่โมเดลสกัดได้
  - `evaluation.json`: ผลประเมินความแม่นยำของโมเดล (มีค่าชี้วัดเช่น CER, WER, จำนวนที่ดึงพลาด ฯลฯ)
  - `comparison.csv`: ตารางสรุปผลลัพธ์ของแต่ละ Attribute
  - `intermediate_vlm.md` (ถ้ามี): ไฟล์ผลลัพธ์ข้อความดิบชั่วคราวที่ได้จากการทำ OCR ก่อนส่งต่อให้ Text LLM

---

## ⚙️ Pipelines การทำงาน

ระบบรองรับกระบวนการดึงข้อมูล 3 รูปแบบ เพื่อเปรียบเทียบประสิทธิภาพ:

1. **Baseline (`--pipeline baseline`)**: การทำงานแบบดั้งเดิม ใช้ OpenCV + Tesseract (OCR) จับคู่กับ Regular Expression (Regex) เป็นเส้นฐานในการเปรียบเทียบ
2. **VLM (`--pipeline vlm`)**: ใช้ Vision-Language Model (`scb10x/typhoon-ocr1.5-3b`) ในการอ่านภาพแปลงเป็นข้อความ (Markdown) จากนั้นส่งให้ Text Model (`qwen3:4b`) จัดรูปแบบเป็น JSON (ใช้การทำงานแบบแบ่ง Chunk เพื่อไม่ให้เกิน Context length ของโมเดล)
3. **Text (`--pipeline text`)**: ใช้วิธีดึงข้อความจาก Digital PDF โดยตรง (ข้ามขั้นตอน OCR) แล้วส่งต่อให้ Text Model (`qwen3:4b`) จัดเป็น JSON ซึ่งทำงานได้ **เร็วกว่าและแม่นยำกว่า** หากไฟล์ PDF ต้นฉบับมีข้อความฝังมาให้ (Digital PDF)

## 🚀 วิธีการใช้งาน (Usage)

ตรวจสอบความพร้อมของระบบ (เครื่องมือ, Ollama, Models):
```bash
python3 lab7b_curriculum.py --check
```

รัน Pipeline ครบทุกขั้นตอนเพื่อประเมินผล:
```bash
python3 lab7b_curriculum.py \
    --input data/DSBA_curriculum.pdf \
    --gt gt/DSBA_academic_plan_coop.json \
    --pipeline all \
    --out output/
```

กรณีต้องการประหยัดเวลาด้วยการเลือกรันเฉพาะหน้า (เพราะแผนการศึกษาอาจอยู่แค่ไม่กี่หน้า):
```bash
python3 lab7b_curriculum.py \
    -i data/DSBA_curriculum.pdf \
    --pages 42-58 \
    -g gt/DSBA_academic_plan_coop.json
```

## ⚠️ ข้อควรระวังและปัญหาที่พบบ่อย (Observations)

จากผลลัพธ์การทดสอบในรอบก่อนหน้า พบว่ามีโอกาสที่ **VLM Pipeline จะล้มเหลวโดยสมบูรณ์** หากโมเดล OCR ไม่สามารถอ่านตารางในภาพได้
- **อาการที่พบ**: ไฟล์ขั้นกลาง (`intermediate_vlm.md`) มีเพียงโค้ด LaTeX (เช่น `\usetikzlibrary`) วนซ้ำไปมาโดยไม่มีข้อความรายวิชาเลย
- **ผลที่ตามมา**: เมื่อข้อความต้นฉบับพัง โมเดล Text (`qwen3:4b`) จะพยายามพยากรณ์ข้อมูลขึ้นมาเอง (Hallucination) โดยการใส่รหัสวิชาปลอมๆ และชื่อวิชาทั่วไป เช่น "00000000 วิทยาการข้อมูล"
- **การแก้ไข**: 
  1. หากไฟล์ต้นฉบับสามารถก๊อปปี้ข้อความออกไปได้ (Digital PDF) แนะนำให้ใช้ `--pipeline text` แทน
  2. ลดหน้า/สโคปที่ส่งให้โมเดลอ่าน หรือแบ่ง Chunk เล็กลง (ปรับค่า `PAGES_PER_CHUNK`)
  3. ปรับ Prompt ควบคุมไม่ให้โมเดลเดาข้อมูลเองหากไม่พบเนื้อหาหลักสูตร
