| หลักสูตร (Curriculum Slice) | จำนวนข้อสอบ | Valid SQL Rate | Execution Accuracy | ข้อสอบเชิงปฏิเสธ (Abstain) |

## 2. การทดสอบตัวชี้วัดและการแก้ปัญหา Overfitting ตามทฤษฎีบทที่ 9

### 2.1 Accuracy Paradox & Matthews Correlation Coefficient (MCC)
- **ผลการทดสอบ:** แม้ Accuracy จะสูงถึง 99.0% แต่ Recall = 0.0 และ MCC = 0.0 ยืนยันว่าโมเดลไม่สามารถตรวจจับของปลอมได้เลยแม้แต่หน้าเดียว เมื่อข้อมูลไม่สมดุลเกิน 80:20 ห้ามดู Accuracy เป็นหลัก ให้ดู Recall ของ Rare Class และ MCC เสมอ
- **ตัวชี้วัด:** Accuracy = `99.0%`, Recall = `0.0`, MCC = `0.0`

### 2.2 การวัดความคลาดเคลื่อนต่อเนื่อง (MAE vs RMSE vs MAPE)
- **MAE:** `0.8143` | **RMSE:** `1.8932` | **Gap:** `1.0789`
- **บทวิเคราะห์:** RMSE (1.893) ใกล้เคียงกับ MAE (0.814) แสดงว่าความคลาดเคลื่อนกระจายตัวค่อนข้างสม่ำเสมอทั่วทั้งชุดข้อมูล ไม่มี Outlier รุนแรง

### 2.3 การเปรียบเทียบ CER กับ WER ในงานภาษาไทย
- **CER:** `2.63%` | **WER:** `33.33%`
- **บทวิเคราะห์:** CER = 2.6% ดูดีมาก แต่ WER = 33.3% สูง เนื่องจากผิดเพียงตัวอักษรเดียวแต่ทำให้คำหรือรหัสวิชาทั้งคำถือว่าผิดทั้งหมด ในการทำงานจริงเจ้าหน้าที่ต้องตามแก้ไขทั้งหน่วย จึงเจ็บปวดระดับ WER

### 2.4 การตรวจจับ Learning Curve & วินิจฉัย Overfitting
- **ผลตรวจ:** Overfitting (โมเดลเริ่มจำข้อสอบเก่าที่ Epoch 5 Val loss ดีดขึ้นแต่ Train loss ยังลง)
- **จุด Early Stopping ที่เหมาะสม:** Epoch `5` (Validation Loss ต่ำสุด: `0.68`)
- **คำแนะนำแก้ Overfitting:** 1. เพิ่มข้อมูลตัวอย่างจริง (Data Collection) — ได้ผลดีที่สุดเสมอ
- **คำเตือน (ห้ามแก้ผิดโรค):** ห้ามขยายขนาดโมเดลให้ใหญ่ขึ้น และห้ามเทรนนานขึ้นโดยไม่มี Early Stopping

## 3. สรุปแนวทางนำไปใช้จริงในโปรเจกต์
1. **ระบบสองชั้น (Two-tier Evaluation):** แยกรายงานผลระหว่าง `Valid SQL Rate` และ `Execution Accuracy` เสมอ
2. **Negative Testing:** เมื่อไม่พบข้อมูลในฐานข้อมูล ระบบต้อง Abstain และตอบปฏิเสธทันที ห้ามส่งต่อให้ LLM คาดเดา
3. **General Prompting:** ออกแบบ Prompt ในรูปกฎทั่วไป ไม่เพิ่ม Few-shot เฉพาะเจาะจงเกินไป เพื่อป้องกัน Overfitting
